# macOS Anthropic Computer Use - Implementation Plan

This document outlines the plan to implement the missing functionalities for the Anthropic Computer Use tools (`computer`, `text_editor`, `bash`) within the macOS platform implementation (`src-tauri/mcp-server-os-level/src/platforms/macos/`).

## Phase 1: `computer` Tool - Precise Mouse Control

- **Task:** Implement `move_mouse(x, y)`.
  - **File:** `interaction.rs`
  - **Details:** Create a function that uses `CGEvent::new_mouse_event` with `CGEventType::MouseMoved` to move the cursor to the specified coordinates.
- **Task:** Implement `click_at_coordinates(x, y, button)`.
  - **File:** `interaction.rs`
  - **Details:** Create a function similar to `click_mouse_simulation` but takes coordinates and a button type (left, right, middle). Use appropriate `CGEventType` values (e.g., `LeftMouseDown`, `LeftMouseUp`, `RightMouseDown`, etc.).
- **Task:** Implement `double_click_at_coordinates(x, y)`.
  - **File:** `interaction.rs`
  - **Details:** Extend `click_at_coordinates` or create a new function that performs two click sequences rapidly at the specified coordinates. Use `CGEventSetIntegerValueField` with `kCGMouseEventClickState` set to 2.
- **Task:** Implement `right_click_at_coordinates(x, y)`.
  - **File:** `interaction.rs`
  - **Details:** Use `click_at_coordinates` with the 'right' button parameter.
- **Task:** Implement `drag_mouse(start_x, start_y, end_x, end_y)`.
  - **File:** `interaction.rs`
  - **Details:** Sequence of `MouseMoved` to start, `LeftMouseDown`, `MouseMoved` (or `LeftMouseDragged`) to end, `LeftMouseUp`.
- **Task:** Implement `left_mouse_down(x, y)` / `left_mouse_up(x, y)`.
  - **File:** `interaction.rs`
  - **Details:** Create separate functions using `CGEvent::new_mouse_event` with `CGEventType::LeftMouseDown` and `CGEventType::LeftMouseUp` respectively.
- **Task:** Implement `scroll(direction, amount_px)`.
  - **File:** `interaction.rs`
  - **Details:** Create a function that uses `CGEvent::new_scroll_event` to simulate scrolling. Map `direction` (up, down, left, right) and `amount_px` to the appropriate parameters for axis 1 (vertical) and axis 2 (horizontal).

## Phase 2: `computer` Tool - Precise Keyboard & Clipboard

- **Task:** Implement `key_down(key)` / `key_up(key)`.
  - **File:** `interaction.rs`
  - **Details:** Refactor `press_key` or create new functions to separate the key down (`isPressed: true`) and key up (`isPressed: false`) events generated by `CGEvent::new_keyboard_event`. Handle modifier keys appropriately for hold-down scenarios.
- **Task:** Implement `get_clipboard_contents()`.
  - **File:** `interaction.rs` (or potentially `utils.rs`)
  - **Details:** Use the `pasteboard` crate or Objective-C bridging (`NSPasteboard`) to read text content from the general pasteboard.
- **Task:** Implement `set_clipboard_contents(text)`.
  - **File:** `interaction.rs` (or potentially `utils.rs`)
  - **Details:** Use the `pasteboard` crate or Objective-C bridging (`NSPasteboard`) to write text content to the general pasteboard.

## Phase 3: `text_editor` Tool Enhancements

- **Task:** Implement `select_text(element)`.
  - **File:** `interaction.rs`
  - **Details:** Use accessibility attributes like `kAXSelectedTextRangeAttribute` if available. Alternatively, simulate mouse drag (using the function from Phase 1) or keyboard shortcuts (Shift + Arrow Keys, using functions from Phase 2) based on the element's bounds. Remove the `warn!` placeholder.
- **Task:** Implement fine-grained text manipulation (replace, insert, delete).
  - **File:** `interaction.rs` (or new `text_editing.rs`)
  - **Details:** This is complex. May involve:
    - Setting the selected range (`kAXSelectedTextRangeAttribute`).
    - Using `AXUIElementSetAttributeValue` with `kAXValueAttribute` (if the full value can be set).
    - Simulating keyboard actions (typing, backspace, delete) via functions from Phase 2.
    - Potentially using clipboard functions (copy existing, modify, paste back). Requires careful state management.

## Phase 4: `bash` Tool Implementation

- **Task:** Create `bash.rs` module.
  - **File:** `src-tauri/mcp-server-os-level/src/platforms/macos/bash.rs`
  - **Details:** Define a struct or functions to handle bash command execution.
- **Task:** Implement command execution.
  - **File:** `bash.rs`
  - **Details:** Use `std::process::Command` to spawn a shell (`sh` or `bash`) and execute the provided command string. Capture stdout and stderr. Handle potential errors and timeouts. Implement logic for background commands (`&`). Consider state persistence if required by the tool spec.
- **Task:** Add `bash.rs` to `macos/mod.rs`.

## Phase 5: Integration and Testing

- **Task:** Update `AccessibilityEngine` trait.
  - **File:** `src-tauri/mcp-server-os-level/src/platforms/mod.rs`
  - **Details:** Add new function signatures for all implemented actions (mouse, keyboard, clipboard, bash, text editing).
- **Task:** Implement new trait methods in `MacOSEngine`.
  - **File:** `src-tauri/mcp-server-os-level/src/platforms/macos/engine.rs`
  - **Details:** Add implementations for the new trait methods, calling the corresponding functions created in `interaction.rs`, `utils.rs`, and `bash.rs`.
- **Task:** Update `handle_execute_tool_function`.
  - **File:** `src-tauri/mcp-server-os-level/src/bin/server/handlers/mcp.rs`
  - **Details:** Map the incoming MCP tool function calls (e.g., "computer.move_mouse", "bash.command") to the appropriate `MacOSEngine` methods. Parse parameters correctly.
- **Task:** Add Unit/Integration Tests.
  - **Details:** Create tests where possible, acknowledging the challenges of testing UI automation. Mocking accessibility APIs or using test applications might be necessary. For `bash`, test command execution and output capture.
- **Task:** Run `cargo check` after each significant change.
  - **Details:** Ensure the codebase compiles without errors or warnings frequently throughout the implementation process.

## Phase 6: Documentation and Refinement

- **Task:** Update internal documentation (code comments).
- **Task:** Refactor code for clarity and efficiency.
- **Task:** Final review and testing.
